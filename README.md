# cdnnow-test-golang-14

Переписывание Python-сервера и генератора нагрузки на Go. Цель - рост производительности и наблюдаемости.
Вычисления выполняются исходными библиотеками `c_lib` (C, `add`) и `rust_lib` (Rust, `sub`).
Go-код обеспечивает только инфраструктуру.

## Требования

- Go 1.26.5+
- GCC
- Rust и Cargo
- Linux (`dlopen`, `.so`)
- Docker и Docker Compose - опционально

```sh
make build

# терминал 1
./bin/server

# терминал 2
```

## Конфигурация сервера

- `--host` - адрес привязки. По умолчанию `0.0.0.0`.
- `--port` - порт. По умолчанию `8080`.
- `--c-lib` - путь к `libcalculator.so`.
- `--rust-lib` - путь к `libcalculator_rust.so`.
- `--interval` - период печати `sum` и `sub`, секунды. По умолчанию `5.0`.
- `--type` - тип HTTP-сервера: `stdhttp` (`net/http`) или `fasthttp`. По умолчанию `stdhttp`.
- `--calc-mode` - `sync`, `async`, `parallel`. По умолчанию `async`.
- `--max-conns` - максимальное количество TCP соединений к серверу. По умолчанию `0` - без ограничений.
- `--queue-size` - максимальный размер очереди. Применимо только для `async` и `parallel`. По умолчанию `1024`.
- `--pprof-addr` - адрес pprof. По умолчанию `localhost:6060`, пустая строка отключает.

По умолчанию библиотеки ищутся в каталоге исполняемого файла.

```sh
./bin/server -calc-mode parallel -queue-size 2048
./bin/server -type fasthttp
```

### Режимы

| Режим      | Поведение                              | Когда выбирать |
|:-----------|:---------------------------------------|:---------------|
| `sync`     | клиент ждёт окончания вычислений       | нужно подтверждение, что вычисление выполнено |
| `async`    | ответ сразу после постановки в очередь | нужен гарантированный порядок `add` и `sub` |
| `parallel` | то же, `add` и `sub` параллельны       | порядок `add` и `sub` не важен |

Выбор между `async` и `parallel` зависит от числа ядер и соотношения полезной нагрузки и HTTP-сервера.
На одном ядре `parallel` не дает прироста. На 4 и более ядрах обычно предпочтителен.
Перед выбором снимайте профиль через pprof.

## API

`POST /calc?num=X` - `num` обязательный целый параметр.

- 200 - `ok` (`sync`)
- 202 - `ok` (`async`, `parallel`)
- 400 - некорректный запрос
- 500 - внутренняя ошибка
- 503 - переполнение очереди (`async`, `parallel`)

`GET /ping` - 200 `ok`.

`GET /metrics` - метрики в формате Prometheus.

## Метрики

```text
# пример для calc_ok_1s; остальные *_1s устроены так же
# second - смещение в секундах: 0 - текущая (неполная) секунда, -1 - предыдущая, ..., -59 - самая старая в окне.
calc_ok_1s{second="0"} 123
calc_ok_1s{second="-1"} 123
calc_ok_1s{second="-2"} 123
...
calc_c_duration_ns{quantile="0.95"} 15000
calc_c_duration_ns{quantile="0.99"} 20000
calc_rust_duration_ns{quantile="0.95"} 15000
calc_rust_duration_ns{quantile="0.99"} 20000
```

- `calc_ok_1s` - RPS за каждую секунду последней минуты.
- `calc_overload_1s` - количество отброшенных запросов из-за перегрузки за каждую секунду последней минуты.
- `calc_bad_request_1s` - количество битых запросов за каждую секунду последней минуты.
- `calc_failed_1s` - внутренние ошибки сервера за каждую секунду последней минуты.
- `calc_c_duration_ns`, `calc_rust_duration_ns` - длительность `add` и `sub` в наносекундах.
- Окно 60 секунд, ротация раз в секунду. На дашборде `second=0` отбрасывается.

## Генератор нагрузки

- `--url` - `[http:]//<host>:<port>/<path>[?<query>]` (если схема присутствует - должна быть `http:`)
- `-n` (`--threads`) - число воркеров. По умолчанию `10`.
- `--interval` - пауза между запросами, секунды. `0` - без паузы. По умолчанию `0.1`.
- `--timeout` - таймаут HTTP-запроса, секунды. По умолчанию `5.0`.
- `-d` - время выполнения (например `10s`, `1m`, `1h`). `0` - без ограничения. По умолчанию без ограничения.
- `-j` - максимальная случайная задержка на старте воркера (например `100ms`, `1s`). По умолчанию `0`.
- `-p` - печатать HDR-гистограмму времени выполнения.
- `--no-keep-alive` - отключить keep-alive.
- `--no-probe` - отключить предварительную проверку url перед запуском воркеров.

```bash
./bin/generator -url 'http://localhost:8080/calc' -n 50 -interval 0.001 -p
```

## Ограничения и особенности

- `--timeout` и `--interval` в Go-версии принимают секунды (`sec`) - для обратной
  совместимости с Python-версией. Новые флаги используют стандартный `time.Duration`.
- Генератор не поддерживает `https` (только `http`).
- Генератор резолвит только в IPv4. Проблема: `localhost` может разрезолвиться
  в `::1`, а сервер слушает только на `127.0.0.1`. Решена принудительным IPv4.
- Перед запуском воркеров Go-генератор выполняет тестовый запрос с `num=0` и в случае
  сбоя немедленно завершает работу с ошибкой. Отключается флагом `--no-probe`.
- Go-генератор не выводит id воркера (не несёт полезной информации), логирует только
  первую ошибку и периодически выводит сводку с числом подавленных сообщений -
  чтобы не спамить в лог при высокой нагрузке.
- В режиме `parallel` сервер даёт только отложенную согласованность. В моменте
  `sum` и `sub` могут расходиться.
- В режиме `parallel` перегрузка проверяется только на `Sum`, что в редких случаях
  может привести к блокированию запроса на `Sub`. Так как `sub` не медленнее `add`,
  такая ситуация крайне маловероятна.
- Исходники из ТЗ правились минимально:
  - В `lib.rs` исправлен баг: нагрузочный цикл вырезался при компиляции,
    без правки замеры времени теряли смысл.
  - В Python-генератор добавлен режим keep-alive по умолчанию
    (`--no-keep-alive` - старое поведение) и предварительный резолв в IPv4 -
    для адекватного сравнения с Go-версией.
- Сравнение функций `Rust` и `C` «нечестное»: в `C` стоит `volatile`, а `Rust`
  даже после исправления считает на регистрах. Подробности -
  в [docs/fair-play.md](docs/fair-play.md).
