Пытались сделать Stop идемпотентным и безопасным при параллельной записи. 
in-band stop-cmd через data-каналы порядок не гарантирует: между 
stopped.Load()==false и send'ом может вклиниться stop, и команда уедет в никуда.
Честный фикс — RWMutex вокруг send'а, но это лишний примитив на каждой записи. 
Контракт «продюсеры останавливаются первыми, Stop зовётся один раз» вызывающий 
код и так соблюдает — оригинальный close(stop) / close(numCh) в этих условиях 
корректен.
