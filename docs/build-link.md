# Сборка и ликовка

Резюмирую по итогам раскопок, чтоб осело:

- **`mv` vs `cp -f`** — cargo делает хардлинк `target/release/lib*.so` → `deps/…`, поэтому `mv` после повторной сборки видит «один и тот же файл». Лечится `cp -f`.
- **cbindgen** — `--lang c` (или `language = "C"` в конфиге), иначе тянет C++-хедеры.
- **`-L`/`-l`** — «где искать» и «что искать» при сборке, работают в паре.
- **`-Wl,-rpath,$ORIGIN/../lib`** — путь поиска при запуске, относительно бинаря. `$ORIGIN` доезжает до линкера одним долларом, в ELF попадает буквально.
- **`$$ORIGIN` vs `$ORIGIN`** — эмпирически у тебя сработал один `$`, это и есть истина в твоей сборке.
- **Nix-обёртка gcc** дописывает `-rpath` для всего, до чего дотягивается в командной строке линковки — ни `-L`/`-l`, ни полные пути к `.so` от этого не спасают. Убирается только `patchelf` после сборки, а по-хорошему — билдом через сам Nix.
- **`${SRCDIR}`** — абсолютный путь к папке .go-файла, свойство cgo, не shell.
