[+] **server**: rejectDelay на reject-пути (1ms sleep перед 503).
    Отказ освобождает CPU от вычислений -> HTTP принимает больше ->
    больше отказов -> петля. Sleep возвращает отказу стоимость успеха,
    рвёт петлю. На стенде: 14/2 -> 15/<1. НЕ убирать без перепроверки.

[ ] **server**: rejectDelay спасает только при фиксированном числе
    клиентов (closed-loop). При росте числа клиентов или open-loop
    заливке — скатываемся в livelock: ok->0, CPU только на HTTP+sleep.
    Нужен лимит на in-flight и shed load на входе.

[ ] **server**: проверить reject-path в sync-режиме. Там CPU_reject
